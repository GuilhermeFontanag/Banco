Originado do caso de alocação de capital e excedentes de caixa corporativo na B3, CDBs e Tesouro Selic. Uma arquitetura concebida para substituir planilhas opacas por governança transacional rigorosa.

Rigor Teórico & Engenharia Relacional

Validação das Formas Normais (1FN a 4FN)

Cada forma normal foi comprovada e validada matematicamente no modelo para expurgar anomalias de inserção, alteração e exclusão, garantindo consistência relacional total.

1FN

1ª Forma Normal (Atomicidade dos Campos)

Critério: Todos os atributos contêm apenas valores atômicos (indivisíveis), sem repetição de grupos ou listas concatenadas em uma única coluna.

Aplicação Prática no FinData:

Na tabela ativos_financeiros, a coluna liquidez armazena estritamente um único valor por registro através do tipo controlado ENUM('Diaria', 'No Vencimento', 'D+1', 'D+30'), nunca uma lista como "D+1, D+2". Todas as 10 entidades contêm chaves primárias numéricas inequívocas garantindo a unicidade de cada tupla.

Validado • 100% Atômico
2FN

2ª Forma Normal (Dependência Funcional Total)

Critério: Estando na 1FN, nenhum atributo não-chave depende de apenas uma parte de uma chave primária composta (eliminação de dependências parciais).

Aplicação Prática no FinData:

Na tabela posicao_consolidada_diaria, a identificação lógica do saldo requer a tríade conjunta (id_carteira, id_ativo_financeiro, data_posicao). Colunas métricas como quantidade_saldo e valor_mercado_total dependem da totalidade desses três fatores simultaneamente para existir, sem qualquer dependência fracionada.

Validado • Sem Dependência Parcial
3FN

3ª Forma Normal (Eliminação de Dependências Transitivas)

Critério: Estando na 2FN, nenhum atributo não-chave depende transitivamente de outro atributo não-chave (X → Y → Z).

Aplicação Prática no FinData:

A tabela operacional transacoes_investimento não armazena nome_corretora ou cnpj_corretora. Ela referencia unicamente id_corretora. A razão social e o CNPJ dependem estritamente do identificador próprio na tabela instituicoes_financeiras, impedindo anomalias de atualização em massa se a corretora alterar a denominação.

Validado • Sem Trânsito Indireto
4FN

4ª Forma Normal (Eliminação de Dependência Multivalorada)

Critério: Estando na 3FN (ou BCNF), a relação não contém duas ou mais dependências multivaloradas independentes dentro da mesma tabela (X ↠ Y e X ↠ Z).

Aplicação Prática no FinData:

A tabela carteiras_investimento armazena exclusivamente atributos atrelados diretamente ao ciclo de vida da carteira (nome, objetivo, data_criacao). Qualquer associação independente entre múltiplos gestores e múltiplos limites de compliance seria isolada em tabelas associativas pontuais, prevenindo duplicações cartesianas de linhas.

Validado • Isento de MVD Cartesiana

Agrupamento de Patrimônio Total por Carteira

Consolida a totalização monetária aplicada e a valoração a mercado de cada carteira estratégica na data do fechamento, computando o lucro acumulado absoluto em reais. 

SELECT 
    c.id_carteira,
    c.nome_carteira,
    COUNT(p.id_ativo_financeiro) AS total_ativos,
    SUM(p.valor_investido_total) AS total_investido,
    SUM(p.valor_mercado_total)   AS total_patrimonio,
    ROUND(SUM(p.lucro_prejuizo_acumulado), 2) AS lucro_acumulado_reais
FROM carteiras_investimento c
INNER JOIN posicao_consolidada_diaria p 
    ON c.id_carteira = p.id_carteira
WHERE p.data_posicao = '2026-10-15'
GROUP BY c.id_carteira, c.nome_carteira
ORDER BY total_patrimonio DESC;

DDL MySQL 8.0 • Gerenciador de Ativos

Estrutura DDL consolidada das 10 tabelas relacionais do projeto, com declaração de tipos, Foreign Keys e constraints:

gerenciador_ativos_ddl_full.sql 
-- ========================================================
-- PROJETO: Gestão de Ativos Financeiros (FinData Architecture)
-- DIALETO: MySQL 8.0.46 LTS | ENGINE: InnoDB | CHARSET: utf8mb4
-- ========================================================

CREATE DATABASE IF NOT EXISTS `gerenciador_ativos`
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
USE `gerenciador_ativos`;

-- 1. INSTITUICOES FINANCEIRAS
CREATE TABLE `instituicoes_financeiras` (
  `id_instituicao` INT NOT NULL AUTO_INCREMENT,
  `nome_instituicao` VARCHAR(100) NOT NULL,
  `cnpj` VARCHAR(14) NOT NULL UNIQUE,
  `tipo_instituicao` ENUM('Banco Emissor','Corretora','Distribuidora') NOT NULL,
  `codigo_compe` VARCHAR(5) DEFAULT NULL,
  PRIMARY KEY (`id_instituicao`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 2. TIPOS DE ATIVOS
CREATE TABLE `tipos_ativos` (
  `id_tipo_ativo` INT NOT NULL AUTO_INCREMENT,
  `nome_tipo` VARCHAR(50) NOT NULL,
  `classe_ativo` ENUM('Renda Fixa','Renda Variavel','Fundo de Investimento') NOT NULL,
  `descricao` VARCHAR(255) DEFAULT NULL,
  PRIMARY KEY (`id_tipo_ativo`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 3. CARTEIRAS DE INVESTIMENTO
CREATE TABLE `carteiras_investimento` (
  `id_carteira` INT NOT NULL AUTO_INCREMENT,
  `nome_carteira` VARCHAR(100) NOT NULL,
  `objetivo` VARCHAR(255) DEFAULT NULL,
  `data_criacao` DATE NOT NULL,
  PRIMARY KEY (`id_carteira`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 4. ATIVOS FINANCEIROS
CREATE TABLE `ativos_financeiros` (
  `id_ativo_financeiro` INT NOT NULL AUTO_INCREMENT,
  `id_tipo_ativo` INT NOT NULL,
  `id_instituicao_emissora` INT NOT NULL,
  `ticker_codigo` VARCHAR(30) NOT NULL,
  `nome_ativo` VARCHAR(150) NOT NULL,
  `indexador_taxa` VARCHAR(50) DEFAULT NULL,
  `data_emissao` DATE DEFAULT NULL,
  `data_vencimento` DATE DEFAULT NULL,
  `liquidez` ENUM('Diaria','No Vencimento','D+1','D+30') NOT NULL,
  PRIMARY KEY (`id_ativo_financeiro`),
  KEY `fk_ativos_tipo` (`id_tipo_ativo`),
  KEY `fk_ativos_emissora` (`id_instituicao_emissora`),
  KEY `idx_ativos_ticker` (`ticker_codigo`),
  CONSTRAINT `fk_ativos_emissora` FOREIGN KEY (`id_instituicao_emissora`) REFERENCES `instituicoes_financeiras` (`id_instituicao`) ON DELETE CASCADE,
  CONSTRAINT `fk_ativos_tipo` FOREIGN KEY (`id_tipo_ativo`) REFERENCES `tipos_ativos` (`id_tipo_ativo`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 5. TRANSACOES DE INVESTIMENTO
CREATE TABLE `transacoes_investimento` (
  `id_transacao` INT NOT NULL AUTO_INCREMENT,
  `id_carteira` INT NOT NULL,
  `id_ativo_financeiro` INT NOT NULL,
  `id_corretora` INT NOT NULL,
  `tipo_operacao` ENUM('Compra','Venda','Aporte','Resgate') NOT NULL,
  `data_transacao` DATE NOT NULL,
  `quantidade` DECIMAL(15,4) NOT NULL,
  `preco_unitario` DECIMAL(15,4) NOT NULL,
  `valor_total_bruto` DECIMAL(15,2) NOT NULL,
  PRIMARY KEY (`id_transacao`),
  KEY `fk_transacoes_carteira` (`id_carteira`),
  KEY `fk_transacoes_ativo` (`id_ativo_financeiro`),
  KEY `fk_transacoes_corretora` (`id_corretora`),
  CONSTRAINT `fk_transacoes_ativo` FOREIGN KEY (`id_ativo_financeiro`) REFERENCES `ativos_financeiros` (`id_ativo_financeiro`) ON DELETE CASCADE,
  CONSTRAINT `fk_transacoes_carteira` FOREIGN KEY (`id_carteira`) REFERENCES `carteiras_investimento` (`id_carteira`) ON DELETE CASCADE,
  CONSTRAINT `fk_transacoes_corretora` FOREIGN KEY (`id_corretora`) REFERENCES `instituicoes_financeiras` (`id_instituicao`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 6. PROVENTOS RECEBIDOS
CREATE TABLE `proventos_recebidos` (
  `id_provento` INT NOT NULL AUTO_INCREMENT,
  `id_carteira` INT NOT NULL,
  `id_ativo_financeiro` INT NOT NULL,
  `tipo_provento` ENUM('Dividendo','JCP','Rendimento','Amortizacao') NOT NULL,
  `data_com` DATE NOT NULL,
  `data_pagamento` DATE NOT NULL,
  `valor_bruto_recebido` DECIMAL(15,2) NOT NULL,
  `imposto_renda_retido` DECIMAL(15,2) NOT NULL,
  `valor_liquido_creditado` DECIMAL(15,2) NOT NULL,
  PRIMARY KEY (`id_provento`),
  KEY `fk_proventos_carteira` (`id_carteira`),
  KEY `fk_proventos_ativo` (`id_ativo_financeiro`),
  CONSTRAINT `fk_proventos_ativo` FOREIGN KEY (`id_ativo_financeiro`) REFERENCES `ativos_financeiros` (`id_ativo_financeiro`) ON DELETE CASCADE,
  CONSTRAINT `fk_proventos_carteira` FOREIGN KEY (`id_carteira`) REFERENCES `carteiras_investimento` (`id_carteira`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 7. CUSTOS E TRIBUTACAO
CREATE TABLE `custos_tributacao` (
  `id_custo` INT NOT NULL AUTO_INCREMENT,
  `id_transacao` INT NOT NULL,
  `tipo_custo` ENUM('Corretagem','Emolumentos_B3','Taxa_Custodia','IRRF','IOF') NOT NULL,
  `aliquota_aplicada_pct` DECIMAL(5,2) DEFAULT NULL,
  `valor_deduzido_reais` DECIMAL(15,2) NOT NULL,
  `data_cobranca` DATE NOT NULL,
  PRIMARY KEY (`id_custo`),
  KEY `fk_custos_transacao` (`id_transacao`),
  CONSTRAINT `fk_custos_transacao` FOREIGN KEY (`id_transacao`) REFERENCES `transacoes_investimento` (`id_transacao`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 8. HISTORICO DE COTACOES E TAXAS
CREATE TABLE `historico_cotacoes_taxas` (
  `id_historico` INT NOT NULL AUTO_INCREMENT,
  `id_ativo_financeiro` INT NOT NULL,
  `data_referencia` DATE NOT NULL,
  `preco_abertura` DECIMAL(15,4) DEFAULT NULL,
  `preco_fechamento` DECIMAL(15,4) NOT NULL,
  `taxa_anual_pactuada_pct` DECIMAL(8,4) DEFAULT NULL,
  PRIMARY KEY (`id_historico`),
  KEY `fk_historico_ativo` (`id_ativo_financeiro`),
  KEY `idx_historico_ativo_data` (`id_ativo_financeiro`,`data_referencia`),
  CONSTRAINT `fk_historico_ativo` FOREIGN KEY (`id_ativo_financeiro`) REFERENCES `ativos_financeiros` (`id_ativo_financeiro`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 9. INDICES E BENCHMARKS
CREATE TABLE `indices_benchmarks` (
  `id_indice` INT NOT NULL AUTO_INCREMENT,
  `nome_indice` VARCHAR(50) NOT NULL,
  `data_apuracao` DATE NOT NULL,
  `valor_taxa_diaria_pct` DECIMAL(8,4) NOT NULL,
  `valor_acumulado_ano_pct` DECIMAL(8,4) NOT NULL,
  PRIMARY KEY (`id_indice`),
  KEY `idx_indices_nome_data` (`nome_indice`,`data_apuracao`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 10. POSICAO CONSOLIDADA DIARIA
CREATE TABLE `posicao_consolidada_diaria` (
  `id_posicao` INT NOT NULL AUTO_INCREMENT,
  `id_carteira` INT NOT NULL,
  `id_ativo_financeiro` INT NOT NULL,
  `data_posicao` DATE NOT NULL,
  `quantidade_saldo` DECIMAL(15,4) NOT NULL,
  `custo_medio_unitario` DECIMAL(15,4) NOT NULL,
  `valor_investido_total` DECIMAL(15,2) NOT NULL,
  `valor_mercado_total` DECIMAL(15,2) NOT NULL,
  `lucro_prejuizo_acumulado` DECIMAL(15,2) NOT NULL,
  `rentabilidade_pct_acumulada` DECIMAL(8,4) NOT NULL,
  PRIMARY KEY (`id_posicao`),
  KEY `fk_posicao_ativo` (`id_ativo_financeiro`),
  KEY `idx_posicao_carteira_data` (`id_carteira`,`data_posicao`),
  CONSTRAINT `fk_posicao_ativo` FOREIGN KEY (`id_ativo_financeiro`) REFERENCES `ativos_financeiros` (`id_ativo_financeiro`) ON DELETE CASCADE,
  CONSTRAINT `fk_posicao_carteira` FOREIGN KEY (`id_carteira`) REFERENCES `carteiras_investimento` (`id_carteira`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
